# حاصل ۳۶۰ دسکتاپ — نسخه آزمایشی ۰.۹.۱

این نخستین پوسته دسکتاپ، مستقیماً بر پایه سورس تأییدشده نسخه Android ۰.۸.۲ ساخته می‌شود. هسته محاسبات مالی از نو نوشته نشده است.

## محیط و محدودیت‌های نسخه نخست
- هدف اولیه: Windows 10/11 x64، خروجی نصاب NSIS؛ ساخت برای macOS و Linux قابل طراحی است اما آزموده نشده.
- اطلاعات هر نصب در فضای مخصوص کاربر و پایگاه IndexedDB نگهداری می‌شوند؛ این داده‌ها **رمزگذاری‌شده نیستند**. رمز ورود فقط مانع مشاهده عادی در محیط رابط می‌شود. از رایانه و حساب کاربری با رمز و رمزگذاری دیسک استفاده کنید.
- انتقال بین موبایل و دسکتاپ با پشتیبان JSON: در موبایل «خروجی پشتیبان»، در دسکتاپ «بازیابی» پس از تهیه پشتیبان فعلی. همگام‌سازی زنده هنوز فعال نیست.
- Excel: درون سیستم فایل خوانده/نوشته می‌شود و تمام ارقام و شماره حساب در خروجی متنی هستند. هنگام ورود از بانک، فرمول‌ها پذیرفته نمی‌شوند و مانده‌ها باید پیش از ثبت تأیید شوند.
- PDF: ابتدا متن اصلی استخراج می‌شود؛ برای صفحات اسکن‌شده موتور OCR آفلاین با مدل‌های فارسی (fas) و انگلیسی (eng) اجرا می‌شود و ارقام فارسی، عربی و انگلیسی نرمال می‌شوند. پس از OCR کاربر باید متن را با سند اصلی بررسی و تأیید کند؛ سپس کنترل ریاضی مانده و شناسایی تراکنش تکراری اجرا می‌شود. برخی جدول‌ها و اسکن‌های ضعیف ممکن است به اصلاح دستی متن یا الگوی اختصاصی بانک نیاز داشته باشند. هیچ سند مالی صرفاً براساس OCR خودکار ثبت نمی‌شود.
- اطلاع‌رسانی دسکتاپ فقط هنگام اجرای برنامه است. امکان خروجی ICS برای افزودن دستی یادآورها به Google Calendar یا Outlook فراهم است، اما همگام‌سازی خودکار با سرویس‌ها هنوز پیاده نشده.
- OCR عکس مستقل و گفتار به متن هنوز فعال نیستند؛ OCR مخصوص PDF بانکی فعال است؛ می‌توان عکس را از فایل‌های رایانه انتخاب و به سند پیوست کرد.
- نسخه دسکتاپ به‌صورت مستقل نصب می‌شود، هیچ اطلاعاتی از Android یا برنامه‌های دیگر را خودکار نمی‌خواند.

## ساخت توسط GitHub Actions
شاخه `feature/desktop-windows-v090`، فایل workflow `.github/workflows/build-desktop-win.yml` را اجرا کنید. این workflow بازسازی گام‌به‌گام سورس Android ۰.۸.۲ همراه بررسی SHA را انجام می‌دهد، فایل‌های وب را در desktop/web کپی می‌کند، آزمون Node را اجرا می‌کند و در Windows Runner فایل نصاب EXE تولید می‌کند. خروجی از Artifacts قابل دریافت است.

## ساخت محلی
Node.js 22+، npm، Windows x64:
```sh
# پس از اجرای اسکریپت‌های بازسازی سورس 0.8.2 از ریشه repo
node desktop/prepare.cjs
cd desktop
npm install
npm test
npm run start
npm run build:win
```
بدون امضای کد، ممکن است Windows SmartScreen درباره ناشناس بودن ناشر هشدار دهد. نصب آزمایشی را فقط از مخزن پروژه خود دریافت کنید.

## موارد لازم قبل از اعلام «نسخه عملیاتی»
نصب/آزمایش واقعی ویندوز، import/export XLSX و PDFهای واقعی بانک، بازیابی داده از Android، کارایی با داده زیاد، بررسی مجوز و حریم خصوصی و بررسی امنیت اپلیکیشن در Electron.


## راهنمای OCR بانکی (نسخه ۰.۹.۱)
۱. بخش «ورود گردش بانکی» را باز کنید، فرمت PDF را انتخاب و فایل را از رایانه دریافت کنید.
۲. اگر صفحه PDF اسکن شده باشد، برنامه تصویر آن را به صورت محلی و با موتور Tesseract.js و مدل‌های fas/eng بررسی می‌کند.
۳. متن تشخیص‌داده‌شده و درصد اطمینان/شماره صفحات کم‌اطمینان برای اصلاح نمایش داده می‌شود.
۴. فقط پس از تأیید صریح متن، صورتحساب وارد مرحله پیش‌نمایش و کنترل مانده‌های ریالی می‌شود.
۵. هر گونه مغایرت، تراکنش تکراری یا ستون نامفهوم ثبت نهایی را متوقف می‌کند؛ نتیجه را با فایل اصلی بانک تطبیق دهید.
۶. حداکثر اندازه PDF در این نسخه ۴۰ مگابایت است. حداکثر ۲۰۰ صفحه PDF و ۱۲۰ صفحه برای OCR تصویری پشتیبانی می‌شود. هر صفحه به‌طور مستقل و با سقف ۸ میلیون پیکسل پردازش می‌شود تا حافظه سیستم کنترل شود.

**حریم خصوصی:** OCR داخلی و آفلاین است؛ متن صورتحساب برای این قابلیت به سرویس بیرونی منتقل نمی‌شود. فایل‌های زبان هنگام ساخت، با SHA-256 تأیید و داخل فایل نصب قرار داده می‌شوند. ورود فایل و داده‌ها همچنان نیازمند پشتیبان‌گیری و حفاظت رایانه است.

**آزمون‌های انتشار:** تست مستقل منطق مالی، تشخیص اعداد فارسی و عربی، خواندن PDF تصویری در Windows، و ساخت installer؛ سپس آزمون روی یک PDF واقعی بانک پیش از تأیید عملیاتی.
